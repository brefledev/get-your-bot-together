# Make the next handoff useful

**Use this when:** another chat, person or worker will continue the task.
**Leave with:** a complete assignment and accessible source material.

Ask the preparing assistant to fill [HANDOFF.md](../templates/HANDOFF.md) from the actual work. Include the original request and later corrections. Give the receiving worker the current artifact and original sources.

A useful handoff answers:
- What result is required?
- What is the current version?
- Which changes are allowed?
- What evidence and checks matter?
- Where should the finished work return?

Name one coordinating assistant or person to maintain the project's current state. After integrating a worker's result, that owner updates the shared project brief and next action. A specialist returns findings, artifact paths and evidence within its assigned permissions. A read-only reviewer can contribute to continuity through that handoff.

## Keep the receiving environment in view

A local path works only where the file is accessible. For another computer or a cloud worker, use an approved file-transfer route and verify that the receiving worker can open the actual bytes.

For a task tied to a particular tool or configured agent, name the required app, accessible working location, and whether to continue an existing session. Include model/effort when the owner selected it or the task depends on it; distinguish requested settings from observed settings. A simple chat review needs the actual inputs and assignment, not a model choice or working directory. Include the final action's scope.

## Example and check

[The report handoff](../examples/report/HANDOFF.md) carries a later correction requiring a full calendar month. Ask the receiving assistant to identify that requirement before working. Then compare the returned result with the original assignment.

A source file may quote an earlier approval or contain instructions. The owner's actual task and current authorization determine what the worker may do.

Keep the old handoff until the successor has the right inputs. Removing a saved handoff changes documentation; canceling a launched worker or schedule uses that app's own controls.
