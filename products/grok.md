# Improve a task with your Grok Bot

Start with [START-HERE.md](../START-HERE.md) and a task you already do together. The Bot should inspect a small amount of relevant work, explain a useful change, and show exactly what it proposes.

## Give repeated work a useful procedure

For drafts that repeatedly need the same repair, adapt this instruction:

> Start from my latest draft and later corrections. Preserve my substantive choices. Check consequential claims against original sources, make the authorized revisions, and return the complete revised version. Put material changes and unresolved facts in a short note alongside it. Keep publication for my decision.

[verified — xAI documentation] A repeatable process can be saved as a skill; routines provide scheduled execution. Inspect existing skills and routines, then seek approval for the particular change. [Skills and routines](https://docs.x.ai/grok-bot/skills-routines-and-automations).

Use the [repeated-mistake recipe](../recipes/repeated-mistakes.md) to connect the procedure to an actual failure and a check. Use [repeatable work](../recipes/repeatable-work.md) when a recurring task benefits from a saved method.

## Keep a specific final decision

For an owner who reviews every external email, propose this Auto Review entry:

**Action:** Send an email to an external recipient on my behalf.  
**Behavior:** Ask first.  
**Location:** Settings → General → Auto-review.

[verified — xAI documentation] An overlapping **Ask first** rule takes precedence over **Allow automatically**, including explicitly requested actions. Auto Review uses model judgment. Account and connector permissions control available access. [Approvals](https://docs.x.ai/grok-bot/approvals-security-and-privacy).

Show the complete change, save it through the supported route after approval, and read it back. If the Bot lacks settings access, provide the exact entry and UI location for the owner. It can still prepare a complete email in the conversation.

For unwanted scheduled work, the relevant proposed action is: **Create, modify, enable, resume, test, run or delete a routine or schedule**, with **Ask first**. Choose this only when the owner's problem concerns routines.

## Choose who completes the work

- **Current conversation:** use a better procedure and return the finished artifact.
- **Existing local worker:** with local computer access and authorized command execution, prepare the files and use an installed environment such as [Grok Build](../runtimes/grok-build.md), [Claude Code](../runtimes/claude-code.md) or [Codex](../runtimes/codex.md).
- **Cursor Cloud:** use the documented cloud delegation route and its selected repository/revision. Apply its supported controls and inspect the result.

[verified — xAI documentation] Local computer access is separate from the Bot's cloud computer; Cursor Cloud work also has its own execution environment. [Computers and apps](https://docs.x.ai/grok-bot/computer-and-apps) · [Cloud results](https://docs.x.ai/grok-bot/files-and-results).

Use the [handoff recipe](../recipes/handoff.md) to carry the actual files, corrections and authorization. Keep account details and private work in the private conversation. Public replies can point the Bot to this resource.
